## 1. Project summary

**Purpose.** An interactive MATLAB/Simulink tool that tests and compares three 3-axis attitude controllers for a chaser spacecraft in a 400 km circular LEO orbit approaching the ISS:
1. **Robust SMC**: non-adaptive boundary-layer quaternion sliding-mode control.
2. **Adaptive SMC**: the same sliding surface with online inertia estimation (Slotine–Li regressor, box projection, freeze-on-saturation anti-windup).
3. **PD benchmark**: quaternion PD after Wie & Barba.

**Scope.** Rotational dynamics only. Translational relative motion appears only as an analytic range profile that sets the docking-axis pointing target. The actuators are three orthogonal reaction wheels with torque and momentum saturation. The disturbances are gravity gradient, aerodynamic, SRP and magnetic torques. Sensor noise is optional.

**Engines.**
- The **Simulink** harness is generated by `models/build_ADCS_model.m`.
- The **reference engine** (`src/sim/simulateADCS_ref.m`, fixed-step RK4) runs the same library functions. It is the fallback when Simulink is absent and the cross-check when it is present.

**Status.**
- The project is verified in **MATLAB R2026a Update 5 with Simulink 26.1**:
  - the model generator builds the harness, and all 43 wires are verified after grouping;
  - `run_all_tests` gives 9/9 PASS, including `test_simulink_vs_reference`, which agrees to about 1e-11°;
  - all 7 scenarios × 3 controllers give identical verdicts on both engines (20/21 pass; the one fail is a genuine PD limitation).
- The reference engine is also verified in GNU Octave 8.4.
- **The GUI has not been executed yet** (notes.md I9); it was excluded from the v1.1.0 validation.

**Run and test (MATLAB).**
```matlab
startup_ADCS; build_ADCS_model(true); run_all_tests      % gate: test_simulink_vs_reference must PASS
ADCS_ComparisonApp                                        % GUI
results = runSimulation(scn_nominal(), [1 2 3], 'auto');  % scripted
run_all_scenarios_smoketest                               % 7 scenarios x 3 controllers
check_model_wiring_repair                                 % opt-in: exercises the builder's wire repair (rebuilds twice)
```
In Octave, use `startup_ADCS; run_all_tests` (the Simulink test is skipped automatically).

## 2. Terminology and conventions

| Term / symbol | Meaning |
|---|---|
| **N** | Orbit-plane inertial frame: x = ascending node, z = orbit normal |
| **O (LVLH)** | Local-vertical/local-horizontal frame: o1 along-track (V-bar), o2 = −orbit normal, o3 = nadir |
| **R** | Reference (desired body) frame produced by `referenceAttitude` |
| **B** | Body frame; the wheels are aligned with its axes |
| **q** | Scalar-first quaternion `[q0; qv]`, attitude of B w.r.t. N. `qToDCM(q)` = C_BN, so `v_B = C_BN v_N` |
| **qMult(a,b)** | Composition with `C(qMult(a,b)) = C(a) C(b)` |
| **q_e, ω_e** | Error quaternion `q ⊗ q_r*` (shortest path) and rate error `ω − C(q_e) ω_r` |
| **s** | Sliding variable `ω_e + Λ q_ev` [rad/s] |
| **ω_rv** | Virtual reference rate `C(q_e) ω_r − Λ q_ev` |
| **Y** | 3×6 inertia regressor: `Y θ = J ω̇_rv + ω_rv × (J ω)` |
| **θ, θ̂** | Inertia parameters `[Jxx Jyy Jzz Jxy Jxz Jyz]` and their online estimate [kg·m²] |
| **J_nom / J_true** | Inertia known to the controllers / inertia used by the plant (perturbed by `J_unc_pct`) |
| **Λ, K, η, φ** | SMC surface slope [1/s], s-feedback [N·m·s], switching gain [N·m], boundary layer [rad/s] |
| **Γ** | Adaptation gain [kg·m²·s²] |
| **Proj** | Box projection that keeps θ̂ inside `[theta_min, theta_max]` |
| **freeze_on_sat** | Adaptation anti-windup: θ̂̇ = 0 while the torque command or wheel momentum is saturated |
| **Kp, Kd** | PD gains, `Kp = 2 J_ii ωn²`, `Kd = 2 ζ ωn J_ii` |
| **h_w, τ_rw** | Wheel momentum [N·m·s]; torque applied to the body (= −ḣ_w) [N·m] |
| **GG / Aero / SRP / Mag** | Gravity-gradient, aerodynamic, solar-radiation-pressure and magnetic disturbance torques |
| **PE** | Persistent excitation, needed for θ̂ to converge |
| **target_mode** | 0 inertial hold, 1 LVLH hold, 2 docking approach (line of sight to the ISS), 3 attitude scan (PE) |
| **cfg** | User-level config (human units, may contain char). Built by `initDefaults` or `scn_*` |
| **SC, RG, AG, BG** | Sim-level numeric structs from `buildSimParams`. In Simulink: `SC`, `RobustGains`, `AdaptiveGains`, `BaselineGains` |
| **CONTROLLER_SELECT** | 1 Robust, 2 Adaptive, 3 PD |
| **res** | Result struct with identical fields from both engines (DESIGN_SPEC §6) |
| **M** | Metrics struct from `computeMetrics` (settling time, ss error, torque, momentum, saturation times, chatter, θ̂ error) |

Units are SI internally. Degrees appear only in cfg fields suffixed `_deg` or `_degps`.

## 3. Inter-dependencies (between modules)

```
                    +-------------------+
                    |  app/ (GUI)       |----------------------------+
                    +---------+---------+                            |
                              | cfg                                  |
   config/ (defaults, gains,  v                                      v
   scenarios, metadata) --> src/sim/runSimulation --engine--> src/analysis/
          ^                   |        |                     (metrics, tables,
          |                   |        +--> reference engine   plots, CSV)
   src/config_io/ (save/load) |        |    simulateADCS_ref
                              |        +--> Simulink engine
                              |             runSimulinkBatch --> models/ADCS_ComparisonHarness.slx
                              v                                     (generated by models/build_ADCS_model.m)
                    src/sim/buildSimParams (cfg -> SC,RG,AG,BG)
                              |
      both engines call the SAME library layer each step:
      src/reference -> src/controllers -> src/dynamics (+ src/disturbances) ; all use src/utils
```

| Module | Depends on | Used by |
|---|---|---|
| `src/utils` | — | every other src module, tests |
| `src/reference` | utils | disturbances (orbitGeometry), sim, Simulink `RefGenerator` |
| `src/controllers` | utils | sim, Simulink `ControllerSelect`, config/gains (inertiaToTheta, pdGainsFromBandwidth) |
| `src/dynamics` | utils | sim, Simulink `RigidBodyDynamics3DOF`, `ReactionWheelActuator`, `Sensors` |
| `src/disturbances` | utils, reference | sim, Simulink `DisturbanceTorques` |
| `src/sim` | all of the above, config, models | app, tests, examples |
| `src/analysis` | — (works on `res`, `cfg`) | app, tests, examples |
| `src/config_io` | config (initDefaults) | app, tests |
| `config/` | src/controllers (gain helpers) | sim, app, models, tests |
| `models/` | config, src/sim (buildSimParams), and at run time every library function in the MATLAB Function blocks | src/sim (ensureModelBuilt, runSimulinkBatch) |
| `app/` | config, src/sim, src/analysis, src/config_io | user |

**External dependencies.**
- MATLAB R2021a+.
- Simulink, for the Simulink engine only.
- Parallel Computing Toolbox, optional; used only if a pool is already open.
- GNU Octave 8, for the library and tests only.
- No Aerospace Toolbox is required.

**Code-generation boundary.** Everything under `src/utils`, `src/reference`, `src/controllers`, `src/dynamics` and `src/disturbances` runs inside Simulink MATLAB Function blocks. It must stay codegen-compatible: fixed sizes, numeric-only structs, no cells, strings or printing.

## 4. Intra-dependencies (within modules)

**src/utils**
- `qToDCM` and `qKinMatrix` use `skew3`.
- `dcmToQ` and `qFromRotVec` use `qNormalize`.
- `seedRNG` uses `isOctave`.
- All other utilities are leaves.

**src/reference**
- `referenceAttitude` calls `referenceDCM` and `dcmToQ`, then applies finite differences with step `SC.ref_fd_h` to get ω_r and ω̇_r.
- `referenceDCM` calls `orbitGeometry` and `approachProfile` (mode 2), and `qFromRotVec` (mode 3).

**src/controllers**
- `controllerSelect` dispatches to `robustControlLaw`, `adaptiveControlLaw` or `baselineControlLaw`. It then adds the common +ω×h_w compensation, applies the anti-windup, and clamps.
- The robust and adaptive laws both call `attitudeErrors`, `inertiaRegressor` (which uses `inertiaLinearMap`) and `satVec`. The adaptive law also calls `paramProjection`.
- `baselineControlLaw` calls `attitudeErrors`.
- `trueErrors` (logging and metrics only, using the true state) calls the quaternion utils.
- Invariant: Robust and Adaptive differ only by θ_nom vs θ̂. This is guarded by `test_adaptive_ablation_identity`.

**src/dynamics**
- `rigidBodyDerivatives` uses `qKinMatrix` and `qNormalize` with J_true, and includes −ω×h_w.
- `quatNormalizeState` is a separate block to avoid an algebraic loop.
- `reactionWheelModel` handles torque clamping and the momentum cutoff.
- `sensorModel` applies noise and gyro-bias random walk with 1/√dt scaling.

**src/disturbances**
- `disturbanceTorques` calls `orbitGeometry` and the four `*Torque` functions, and applies `dist_enable .* dist_scale`.

**src/sim**
- `runSimulation` calls `buildSimParams`, then either `simulateADCS_ref` or `ensureModelBuilt` followed by `runSimulinkBatch`, which calls `extractSimulinkResults`.
- `simulateADCS_ref` makes the per-step calls in the same order as the Simulink blocks: `referenceAttitude` → `sensorModel` → `controllerSelect` → `reactionWheelModel` → `disturbanceTorques` → `rigidBodyDerivatives`, plus `quatNormalizeState` and `trueErrors` for outputs. After each RK4 step it clamps h_w and θ̂.
- `buildSimParams` derives n, J_true (seeded, physically valid), q0/ω0 from `referenceAttitude(0)`, and the projection box.

**src/analysis**
- `computeMetrics` produces M, which feeds `evaluatePassFail` (pass/reasons) and then `metricsTable` (header/rows), which feeds `exportMetricsCSV`.
- `plotResultsOnAxes` is independent.

**config/**
- Every `scn_*` calls `initDefaults`, which calls the three `*_default` gain functions. `adaptive_default` reuses `robust_default`, which keeps the ablation.
- `baseline_default` uses `pdGainsFromBandwidth`.
- `listScenarios` is the registry the GUI and smoke test iterate over.
- `gainMetadata` drives the GUI gain tables.

**models/**
- `build_ADCS_model` builds the flat diagram and fixes the size and type of every MATLAB Function port (`portSize`). It wires the diagram from the table `W`, enables logging, and groups it into 7 subsystems.
- After grouping it traces every wire in `W` across the boundaries (`wireIsCorrect`/`traceLeafSource`). It repairs any mis-wire (`repairWire`, `sourceSubsystemPort`, `closeIfOpen`), re-verifies, scans for open ports (`checkNoOpenPorts`), and saves.
- The optional second argument `injectMiswire` is a test hook (`injectWireFault`) used by `tests/check_model_wiring_repair.m`.
- **Any new signal** needs an entry in `W`, and **any new MATLAB Function port** needs an entry in `portSize`; otherwise the build errors.
- It calls `initDefaults` and `buildSimParams` to seed `ADCS_Params.sldd`.
- `pushParamsToDictionary` rewrites the dictionary entries.

**app/**
- `readWidgetsToCfg` and `writeCfgToWidgets` are the only mapping between widgets and cfg; the table is in `app/README_app.md`.
- A run calls `validateCfg`, then `runSimulation`, then `computeMetrics`/`evaluatePassFail`, then refreshes the Results tab.

**tests/**
- `run_all_tests` discovers `test_*.m`.
- `run_all_scenarios_smoketest` iterates `listScenarios`.
- `test_simulink_vs_reference` is the Simulink acceptance gate.
- `check_model_wiring_repair` is opt-in. It is not auto-discovered because it rebuilds the model.

**Ordering constraints.**
1. `startup_ADCS` (paths) must run before `build_ADCS_model`, which must run before any Simulink run.
2. `cfg` must pass through `buildSimParams` before any engine runs; engines never read `cfg` directly.
3. A new cfg field must be added to `initDefaults` first. `loadConfig` then back-fills old saved files.

## 5. Invariants a change must preserve

1. `docs/DESIGN_SPEC.md` is the contract. Change it first, then the code, then log the change in notes.md "Deviations".
2. Result fields and Simulink logged-signal names must stay identical. They are checked in `extractSimulinkResults` and `simulateADCS_ref`.
3. Controllers never read `SC.J_true`.
4. Every source file follows the commenting standard in PROJECT_RULES R2. No double-quoted strings in `.m` files.
5. Gates: `run_all_tests` all PASS, the smoke test has no non-finite or norm failures, and the Simulink cross-check passes whenever MATLAB is available. The model build must report all wires verified, with no open ports.
6. Update this file and `notes.md` together whenever the structure, dependencies or results change.
7. MATLAB is driven through the MCP connector's single window only (PROJECT_RULES R8/R9). Before every MATLAB call, check `_tmp/status.txt` and wait for as long as it reads BUSY.
